Yes. This reply now starts with the direct answer, keeps your question just above it, and marks each section with one fixed symbol, so you can jump to the part you want.

Every marker keeps a single meaning: a tick is only a confirmed result, a snail only work still running, an eye only the start of a check. There are 16 of them, and nothing outside the list is used, however fitting another emoji might look.

Colour is rationed the same way. Each coloured highlight makes sense on its own. You can start reading at its first word and understand it without the surrounding text. The rest of the explanation stays white. Red means you must read it, green marks the confirmed result, orange a warning.

The return arrow stays beside the opening answer, even when a table or list follows. Other markers sit above a multi-block section with a small ▾ caret, and apply until the next marker.

In a hurry, read only the ⮑ line; the other sections are there when you want the detail.

Details

⮑

Direct answer

A direct answer to your question. The question or excerpt it answers sits in a quote just above it, and the answer still makes sense if you skip the quote.

Placement: keep the return arrow beside the opening answer, even when a table or list follows. Other markers stay inline for short statements, or sit with a small ▾ caret above multi-block sections. Never after the text, centred or indented. Markers render at LaTeX \huge size; the caret and prose stay normal size. The caret is a visual cue, not a dropdown control.

All 16 markers

Sixteen markers, one meaning each

The same marker means the same thing in every reply. Nothing outside this list is used, and if no meaning fits, the section stays unmarked. Pick one to read its rule.

  • Direct answer
  • Confirmed success
  • Failure
  • Starting a check
  • Work in progress
  • Actual bug
  • Information
  • Your action
  • Unexpected
  • Caution
  • Missing information
  • Recommendation
  • Trade-offs
  • External blocker
  • Skill use
  • Added beyond your request
  • ↗Opening link, not a marker

Activity and outcome stay apart: 👀 starts a check, 🐌 is work still running, and a finished check reports ✅, 🐞 or ❌. Finding a bug is not a failed review. The ↗ after a reference opens it: your original message, a skill, a file or a passage.

Four highlight colours, plus skill names

  • Red · critical, you must read this
  • Green · the confirmed result, for a glance
  • Orange · a warning or kind-of-important detail
  • Cyan · a selected piece of information worth noticing
  • Magenta serif · a skill name, followed by its own ↗ link

Every red, green, orange or cyan highlight must make sense on its own, starting from its first word. Include enough subject and context; a short complete sentence is fine. Highlight selectively in the same sans-serif as the prose, without underlining, and keep supporting explanation white. Do not colour whole multi-sentence explanations, links, paths or code. Links keep their ordinary link colour and carry no extra meaning. Code stays monospace.

In Codex these highlights are written as inline LaTeX, for example \(\color{#22c55e}{\textsf{All checks passed.}}\); this page reproduces the result with CSS.

Markdown and code editor

Every file a reply links to, including Your message and the skill itself, opens in this self-contained page: formatted Markdown, a highlighted target line, and a real editor with syntax colours, search and replace, undo and line numbers. Files stay in your browser.

viewer.html · sample document↗
What it can and cannot do

The page is a snapshot and does not watch the disk. Download any edits before opening another file in this pane. Open the editor in its own tab to use the browser’s file picker. Saving directly works only for a file you picked with Open file in a browser that supports it; otherwise use Download copy. Snapshots never write back to their original.

UTF-8 text up to 5 MB. Local raster images are embedded best effort by the generator; remote images do not load, raw HTML in Markdown is escaped, and nothing is uploaded anywhere. There is no terminal and no code execution. Markdown, JavaScript, TypeScript, Python, JSON, HTML, CSS, SQL, YAML, shell, Rust and Go get syntax colours.

Use it in Codex

Clone the skill into your Codex skills folder. If that folder already exists, the clone fails rather than replacing it; compare before installing.

git clone https://github.com/EthanSK/response-preferences.git ~/.codex/skills/response-preferences

Then add one line to your global or project AGENTS.md:

Use $response-preferences for all replies.

Python 3.9+ generates viewers and message-context files; no Node build is needed. The defaults follow Ethan’s preferences: edit SKILL.md to change them. A pre-send checker catches structural mistakes such as missing magenta skill names, missing links and misplaced markers. Automated tests run on every push. These are agent instructions, not a change to the Codex app: the checks cannot guarantee that a model always follows the rules or uses a marker with the right meaning.

Notification titles condense your question; the text underneath has a status icon and a brief answer summary. Titles contain no emoji; the integration checks one title line and two answer lines. The wording is specified, but native delivery is a separate optional integration that this repository does not ship. Replies never carry hidden metadata.
