Details

⮑

Direct answer

A direct answer to your question. The question or excerpt it answers sits in a quote just above it, and the answer still makes sense if you skip the quote.

Placement: keep the return arrow beside the opening answer, even when a table or list follows. Other markers stay inline for short statements, or sit with a visible ⌄ chevron above multi-block sections. Never after the text, centred or indented. Working messages use plain normal-size markers, including 🧠, with a normal-size chevron for standalone sections. Final replies use LaTeX \huge markers; their smaller chevron uses \Large, raised 0.3em toward the emoji’s vertical centre. Prose and table labels stay normal size. The caret is a visual cue, not a dropdown control.

Activity and outcome stay apart: 👀 starts a check, 🐌 is work still running, and a finished check reports ✅, 🐞 or ❌. Finding a bug is not a failed review. The ↗ after a reference opens it: your original message, a skill, a file or a passage.

Highlight colours, skill names and topic reminders

  • Red · critical, you must read this
  • Green · the confirmed result, for a glance
  • Orange · a warning or kind-of-important detail
  • Cyan · a selected piece of information worth noticing
  • Muted lavender · a closing reminder with a brief overview, then a second sentence giving specific context
  • Magenta serif · a skill name, followed by its own ↗ link

Every red, green, orange or cyan highlight must make sense on its own, starting from its first word. Include enough subject and context; a short complete sentence is fine. Highlight selectively and keep supporting explanation white. In final replies, make the first bold clue in each paragraph name the subject, so later clues have context when you glance back. Prefer a short useful bold clue in final prose sentences, or let a self-contained colour highlight carry it. Working updates stay plain. Retain negatives and conditions. Exact quotations, code and links keep their original formatting. Do not colour whole multi-sentence explanations, links, paths or code. Links keep their ordinary link colour and carry no extra meaning. Code stays monospace.

Whenever a reply includes a table, colour its important rows with these same meanings and bold the key words, including short cell values. Keep routine rows neutral and wording brief so the key distinctions stand out. Do not invent errors or use every colour just for decoration.

Example itemWhat to notice
Routine lookupStandard handling
Recommended optionReuses existing state
Permission caveatAccess is still unverified
Upload failureNo file was uploaded
Saved changesThe requested change is saved

Automated tests, lint and routine automated checks stay ordinary text. Manual browser/app checks use 🖥️ with explicit status wording, and green only for confirmed manual success. A project can add user-approved mappings in its existing instructions; it cannot invent new meanings or silently replace the global set.

Keep literal names such as C# and sample_tool in ordinary text or inline code, and put short scanning clues near them. Keep percentages outside the LaTeX box too. If a short styled fragment needs one of these characters, escape it as C\#, sample\_tool, 54\% or A \& B.

Write working updates as plain Markdown. In final replies, use Markdown bold for scanning and short colour expressions when they help. The optional checker uses bundled KaTeX to diagnose a tricky expression or maintain the skill; it does not run before every reply. It needs Node.js on PATH or RESPONSE_PREFERENCES_NODE, with no npm install or network for a copied skill. Automatic reply repair and completion-hook continuation turns are not used.

In Codex, a colour highlight can use \(\color{#22c55e}\text{The requested change is saved.}\). The examples on this page use CSS. Codex can keep a LaTeX expression on one line, so keep styled expressions below 64 approximate visible characters and let surrounding Markdown wrap. This CSS preview does not verify native Codex wrapping.

Markdown and code editor

Every file a reply links to, including Your message and the skill itself, opens in this self-contained page: formatted Markdown, a highlighted target line, and a real editor with syntax colours, search and replace, undo and line numbers. Files stay in your browser.

viewer.html · sample document↗
What it can and cannot do

The page is a snapshot and does not watch the disk. Download any edits before opening another file in this pane. Open the editor in its own tab to use the browser’s file picker. Saving directly works only for a file you picked with Open file in a browser that supports it; otherwise use Download copy. Snapshots never write back to their original.

UTF-8 text up to 5 MB. Local raster images are embedded best effort by the generator; remote images do not load, raw HTML in Markdown is escaped, and nothing is uploaded anywhere. There is no terminal and no code execution. Markdown, JavaScript, TypeScript, Python, JSON, HTML, CSS, SQL, YAML, shell, Rust and Go get syntax colours.
