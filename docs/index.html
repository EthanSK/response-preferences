Yes. This reply’s format now starts with the direct answer, keeps your question just above it, and marks each section with one fixed symbol, so you can jump to the part you want.

Working messages use small markers, including the brain beside a skill announcement. Final replies use large markers, so you can distinguish the finished answer at a glance.

Every marker keeps a single meaning: a tick is only a confirmed result, a snail only work still running, an eye only the start of a check. There are 18 global markers, and only user-approved project extensions add to the list, however fitting another emoji might look.

Colour is selected by meaning. Each coloured highlight makes sense on its own. You can start reading at its first word and understand it without the surrounding text. The rest of the explanation stays white. Red means you must read it, green marks the confirmed result, orange a warning.

Final completion statements use green, including committed, merged, saved and deployed outcomes: The change is committed. Automated tests and lint stay uncoloured; a passing check alone does not mean the task is finished.

A muted-lavender topic reminder ends every message, including working updates, with two short sentences. The first sentence gives the overview; the second adds the specific action, problem or next step, so you can recover the context without rereading the reply. Your quoted question stays above its answer.

Only the final reply has an attention finger: usually one 🫵 for your action or 👉 for the main takeaway; two only for distinct important items. Working updates have no attention fingers.

Underlined scanning cues start each paragraph by naming what the details are about, so a later cue makes sense when you glance back.

The skill-update decisions remain agent-based: a helper tracks the date, and the agent checks the repository.

Each sentence still highlights useful clues, without underlining everything. Negatives and conditions stay with the words they qualify; “not uploaded” must not become just “uploaded”.

The return arrow stays beside the opening answer, even when a table or list follows. Other markers sit above a multi-block section with a visible ⌄ chevron, and apply until the next marker.

In a hurry, read only the ⮑ line; the other sections are there when you want the detail.

Details

⮑

Direct answer

A direct answer to your question. The question or excerpt it answers sits in a quote just above it, and the answer still makes sense if you skip the quote.

Placement: keep the return arrow beside the opening answer, even when a table or list follows. Other markers stay inline for short statements, or sit with a visible ⌄ chevron above multi-block sections. Never after the text, centred or indented. Working messages use plain normal-size markers, including 🧠, with a normal-size chevron for standalone sections. Final replies use LaTeX \huge markers; their smaller chevron uses \Large, raised 0.3em toward the emoji’s vertical centre. Prose and table labels stay normal size. The caret is a visual cue, not a dropdown control.

All 18 global markers

Eighteen global markers, one meaning each

The same marker means the same thing in every reply. User-approved project extensions can add meanings within that project; otherwise, if no global meaning fits, the section stays unmarked. Pick one to read its rule.

Activity and outcome stay apart: 👀 starts a check, 🐌 is work still running, and a finished check reports ✅, 🐞 or ❌. Finding a bug is not a failed review. The ↗ after a reference opens it: your original message, a skill, a file or a passage.

Highlight colours, skill names and topic reminders

  • Red · critical, you must read this
  • Green · the confirmed result, for a glance
  • Orange · a warning or kind-of-important detail
  • Cyan · a selected piece of information worth noticing
  • Muted lavender · a closing reminder with a brief overview, then a second sentence giving specific context
  • Magenta serif · a skill name, followed by its own ↗ link

Every red, green, orange or cyan highlight must make sense on its own, starting from its first word. Include enough subject and context; a short complete sentence is fine. Highlight selectively in the same sans-serif as the prose, and keep supporting explanation white. Make the first underline in each paragraph name the subject, so later underlined details have context when you glance back. Underline the most useful words in every assistant prose sentence, inside colours as well as ordinary text; retain negatives and conditions. Colours remain understandable clauses, while underlines pick out scanning clues. Exact quotations, code and links keep their original formatting. Do not colour whole multi-sentence explanations, links, paths or code. Links keep their ordinary link colour and carry no extra meaning. Code stays monospace.

Automated tests, lint and routine automated checks stay ordinary text. Manual browser/app checks use 🖥️ with explicit status wording, and green only for confirmed manual success. A project can add user-approved mappings in its existing instructions; it cannot invent new meanings or silently replace the global set.

In Codex these highlights are written as inline LaTeX, for example \(\color{#22c55e}{\textsf{The requested change is saved.}}\); this page reproduces the result with CSS. Codex can keep a whole LaTeX text box on one line, so use short self-contained highlights and wrapping prose for supporting details. Underlines and topic reminders need the same care. The checker rejects prose expressions over 80 approximate visible characters; this guardrail is not a guarantee at every pane width or zoom. This CSS preview does not verify native Codex wrapping.

Markdown and code editor

Every file a reply links to, including Your message and the skill itself, opens in this self-contained page: formatted Markdown, a highlighted target line, and a real editor with syntax colours, search and replace, undo and line numbers. Files stay in your browser.

viewer.html · sample document↗
What it can and cannot do

The page is a snapshot and does not watch the disk. Download any edits before opening another file in this pane. Open the editor in its own tab to use the browser’s file picker. Saving directly works only for a file you picked with Open file in a browser that supports it; otherwise use Download copy. Snapshots never write back to their original.

UTF-8 text up to 5 MB. Local raster images are embedded best effort by the generator; remote images do not load, raw HTML in Markdown is escaped, and nothing is uploaded anywhere. There is no terminal and no code execution. Markdown, JavaScript, TypeScript, Python, JSON, HTML, CSS, SQL, YAML, shell, Rust and Go get syntax colours.

A pre-send checker catches structural mistakes such as missing magenta skill names, missing links and misplaced markers. Automated tests run on every push. These are agent instructions, not a change to the Codex app: the checks cannot guarantee that a model always follows the rules or uses a marker with the right meaning.

Notification titles condense your question; the text underneath has a status icon and a brief answer summary. Titles contain no emoji; the integration checks one title line and two answer lines. The wording is specified, but native delivery is a separate optional integration that this repository does not ship. Replies never carry hidden metadata.
